ಡೇಟಾ ಟೈಪ್ (Data Type) ಎಂದರೇನು?

ನಮ್ಮ ದೈನಂದಿನ ಜೀವನದಲ್ಲಿ ಒಂದು ಉದಾಹರಣೆ ತೆಗೆದುಕೊಳ್ಳೋಣ: ನಾವು ನೀರನ್ನು ಬಾಟಲಿಯಲ್ಲಿ ತುಂಬುತ್ತೇವೆ, ಅಕ್ಕಿಯನ್ನು ಡಬ್ಬದಲ್ಲಿ ಹಾಕುತ್ತೇವೆ, ಹಾಗೆಯೇ ಹಣವನ್ನು ಪರ್ಸ್‌ನಲ್ಲಿ ಇಡುತ್ತೇವೆ. ಅಂದರೆ, ಪ್ರತಿಯೊಂದು ವಸ್ತುವಿಗೂ (ನೀರು, ಅಕ್ಕಿ, ಹಣ) ಅದರದೇ ಆದ ಗುಣವಿದೆ ಮತ್ತು ಅದನ್ನು ಶೇಖರಿಸಲು ಒಂದು ನಿರ್ದಿಷ್ಟ ವಿಧಾನವಿದೆ.

ಅದೇ ರೀತಿ, ಪ್ರೋಗ್ರಾಮಿಂಗ್‌ನಲ್ಲಿ ನಾವು ಬಳಸುವ ಮಾಹಿತಿಯು (Data) ಯಾವ ಗುಂಪಿಗೆ ಸೇರುತ್ತದೆ - ಅಂದರೆ ಅದು ಅಕ್ಷರವೇ, ಅಂಕಿಯೇ, ಪಟ್ಟಿಯೇ ಅಥವಾ ಸರಿಯೋ/ತಪ್ಪೋ - ಎಂಬುದನ್ನು ಕಂಪ್ಯೂಟರ್‌ಗೆ ತಿಳಿಸುವ ವಿಧಾನವೇ Data Types.

JavaScript ನಲ್ಲಿ ಒಂದು ವೇರಿಯೇಬಲ್ (Variable) ಒಳಗೆ ಯಾವ ರೀತಿಯ ಡೇಟಾ ಇದೆ ಎಂದು ಹೇಳಲು ಇದನ್ನು ಬಳಸಲಾಗುತ್ತದೆ.

ಚಿತ್ರ 1: ದೈನಂದಿನ ವಸ್ತುಗಳು ಮತ್ತು ಕೋಡಿಂಗ್ ಡೇಟಾ ಟೈಪ್ಸ್ ಹೋಲಿಕೆ

ಜಾವಾಸ್ಕ್ರಿಪ್ಟ್‌ನಲ್ಲಿ ಡೇಟಾ ಟೈಪ್‌ಗಳನ್ನು ಮುಖ್ಯವಾಗಿ 2 ಭಾಗಗಳಾಗಿ ವಿಂಗಡಿಸಲಾಗಿದೆ:

  1. Primitive Data Types (ಮೂಲಭೂತ ಡೇಟಾ ಟೈಪ್‌‌ಗಳು - ಒಟ್ಟು 7)
  2. Non-Primitive / Reference Data Types (ಸಂಕೀರ್ಣ ಡೇಟಾ ಟೈಪ್‌ಗಳು - Object)

ನಿಮ್ಮ ಮನೆಯಲ್ಲಿ ಅಡುಗೆಮನೆ ಅಥವಾ ಆಟದ ಕೋಣೆಯನ್ನು ಒಮ್ಮೆ ಕಲ್ಪಿಸಿಕೊಳ್ಳಿ: ನೀರನ್ನು ಇಡಲು ಬಾಟಲಿ, ಪೆನ್ಸಿಲ್ ಇಡಲು ಪೆನ್ಸಿಲ್ ಬಾಕ್ಸ್, ಮತ್ತು ಊಟ ಕಟ್ಟಲು ಟಿಫಿನ್ ಬಾಕ್ಸ್ ಬಳಸುತ್ತೇವೆ ಅಲ್ಲವೇ? ನೀರನ್ನು ಪೆನ್ಸಿಲ್ ಬಾಕ್ಸ್‌‌ನಲ್ಲಿ ಹಾಕಲು ಸಾಧ್ಯವಿಲ್ಲ! ಅದೇ ರೀತಿ, ಕಂಪ್ಯೂಟರ್‌ನಲ್ಲಿ ನಾವು ಮಾಹಿತಿಯನ್ನು (Data) ಸೇವ್ ಮಾಡುವಾಗ, ಅದು ಸಂಖ್ಯೆಯೇ, ಹೆಸರೇ ಅಥವಾ ಬೇರೆಯದೇ ಮಾಹಿತಿಯೇ ಎಂದು ಕಂಪ್ಯೂಟರ್‌ಗೆ ತಿಳಿಸಬೇಕಾಗುತ್ತದೆ. ಹೀಗೆ ಮಾಹಿತಿಯ ವಿಧಗಳನ್ನು ಗುರುತಿಸುವುದನ್ನೇ ಜಾವಾಸ್ಕ್ರಿಪ್ಟ್‌ನಲ್ಲಿ Data Types (ಡೇಟಾ ಟೈಪ್ಸ್) ಎಂದು ಕರೆಯುತ್ತಾರೆ.

ಜಾವಾಸ್ಕ್ರಿಪ್ಟ್‌ನಲ್ಲಿ ಡೇಟಾ ಟೈಪ್‌ಗಳನ್ನು ಮುಖ್ಯವಾಗಿ 2 ಭಾಗಗಳಾಗಿ ವಿಂಗಡಿಸಲಾಗಿದೆ:

  1. Primitive Data Types (ಮೂಲಭೂತ ಡೇಟಾ ಟೈಪ್‌‌ಗಳು - ಒಟ್ಟು 7)
  2. Non-Primitive / Reference Data Types (ಸಂಕೀರ್ಣ ಡೇಟಾ ಟೈಪ್‌ಗಳು - Object)
ಚಿತ್ರ 2: JavaScript Data Types ವರ್ಗೀಕರಣ ಚಾರ್ಟ್

ಹಂತ 1: Beginner Level — ಮೂಲಭೂತ ಡೇಟಾ ಟೈಪ್‌‌ಗಳು (Primitive Types)

ಇವು ಒಂದೇ ಒಂದು ಸರಳವಾದ ಮಾಹಿತಿಯನ್ನು ಇಟ್ಟುಕೊಳ್ಳುವ ಚಿಕ್ಕ ಡಬ್ಬಿಗಳಂತೆ ಕೆಲಸ ಮಾಡುತ್ತವೆ. ಇವುಗಳಲ್ಲಿ 7 ವಿಧಗಳಿವೆ:

1. String (ಪದಗಳು ಅಥವಾ ಅಕ್ಷರಗಳು)

ಯಾವುದೇ ಹೆಸರು, ವಾಕ್ಯ ಅಥವಾ ಅಕ್ಷರಗಳನ್ನು ಬರೆಯಲು ಇದನ್ನು ಬಳಸುತ್ತೇವೆ. ಇದನ್ನು ಯಾವಾಗಲೂ ಸಿಂಗಲ್ ಕೋಟ್ಸ್ (' ') ಅಥವಾ ಡಬಲ್ ಕೋಟ್ಸ್ (" ") ಒಳಗೆ ಬರೆಯಬೇಕು.

  • ಮಕ್ಕಳ ಉದಾಹರಣೆ: ನಿಮ್ಮ ಹೆಸರಿನ ಸ್ಟಿಕ್ಕರ್.
JavaScript
let studentName = "ರಾಹುಲ್";
let message = 'ನಮಸ್ಕಾರ ಕರ್ನಾಟಕ!';

2. Number (ಸಂಖ್ಯೆಗಳು)

ಎಲ್ಲಾ ರೀತಿಯ ಸಂಖ್ಯೆಗಳು—ಪೂರ್ಣ ಸಂಖ್ಯೆ ಇರಲಿ ಅಥವಾ ದಶಮಾಂಶ (Decimal) ಸಂಖ್ಯೆ ಇರಲಿ—ಇದರಲ್ಲಿ ಬರುತ್ತವೆ. ಇದಕ್ಕೆ ಕೋಟ್ಸ್ ಹಾಕುವಂತಿಲ್ಲ.

  • ಮಕ್ಕಳ ಉದಾಹರಣೆ: ನಿಮ್ಮ ವಯಸ್ಸು ಅಥವಾ ಪರೀಕ್ಷೆಯಲ್ಲಿ ಬಂದ ಅಂಕಗಳು.
JavaScript
let age = 12;
let price = 99.50;

3. Boolean (ಹೌದು ಅಥವಾ ಇಲ್ಲ)

ಇದರಲ್ಲಿ ಕೇವಲ ಎರಡೇ ಎರಡು ಉತ್ತರಗಳಿರುತ್ತವೆ: true (ಸರಿ/ಹೌದು) ಅಥವಾ false (ತಪ್ಪು/ಇಲ್ಲ).

  • ಮಕ್ಕಳ ಉದಾಹರಣೆ: ಕೋಣೆಯ ಲೈಟ್ ಆನ್ ಆಗಿದೆಯೇ (true) ಅಥವಾ ಆಫ್ ಆಗಿದೆಯೇ (false)?
JavaScript
let isRaining = true;
let HomeworkDone = false;

4. Undefined (ಇನ್ನೂ ಏನನ್ನೂ ಹಾಕದ ಡಬ್ಬಿ)

ನಾವು ಒಂದು ಡಬ್ಬಿಯನ್ನು (Variable) ತಂದಿದ್ದೇವೆ, ಆದರೆ ಅದರೊಳಗೆ ಇನ್ನೂ ಯಾವುದೇ ವಸ್ತುವನ್ನು ಹಾಕಿಲ್ಲ ಎಂದರೆ ಅದು undefined ಆಗಿರುತ್ತದೆ.

JavaScript
let futureScore; 
console.log(futureScore); // Output: undefined

5. Null (ಉದ್ದೇಶಪೂರ್ವಕವಾಗಿ ಖಾಲಿ ಇಟ್ಟ ಡಬ್ಬಿ)

ಡಬ್ಬಿ ಇದೆ, ಆದರೆ ಅದರೊಳಗೆ ಸದ್ಯಕ್ಕೆ "ಏನೂ ಇಲ್ಲ" ಎಂದು ನಾವೇ ಸ್ವತಃ ಖಾಲಿ ಬಿಟ್ಟಿರುವ ಸ್ಥಿತಿ.

Undefined vs Null ವ್ಯತ್ಯಾಸ: ನೀವು ಹೊಸ ಟಿಫಿನ್ ಬಾಕ್ಸ್ ಕೊಂಡು ತಂದಾಗ ಅದು ತಾನಾಗಿಯೇ ಖಾಲಿ ಇರುತ್ತದೆ (Undefined). ಆದರೆ ಊಟ ಮುಗಿದ ಮೇಲೆ ಬಾಕ್ಸ್ ತೊಳೆದು "ಇದರಲ್ಲಿ ಈಗ ಏನೂ ಇಲ್ಲ" ಎಂದು ಎತ್ತಿಡುವುದು (Null).
ಚಿತ್ರ 3: Undefined ಮತ್ತು Null ನಡುವಿನ ವ್ಯತ್ಯಾಸ (ಟಿಫಿನ್ ಬಾಕ್ಸ್ ಉದಾಹರಣೆ)
JavaScript
let selectedToy = null; // ಸದ್ಯಕ್ಕೆ ಯಾವುದೇ ಆಟಿಕೆ ಆಯ್ಕೆ ಮಾಡಿಲ್ಲ

6. BigInt (ಅತಿ ದೊಡ್ಡ ಸಂಖ್ಯೆಗಳು)

ಸಾಮಾನ್ಯ Number ಡೇಟಾ ಟೈಪ್‌ನಲ್ಲಿ ಒಂದು ಮಿತಿಗಿಂತ (253 - 1) ದೊಡ್ಡ ಸಂಖ್ಯೆಗಳನ್ನು ಸೇವ್ ಮಾಡಲು ಸಾಧ್ಯವಿಲ್ಲ. ಬಾಹ್ಯಾಕಾಶದ ದೂರ ಅಥವಾ ದೊಡ್ಡ ಲೆಕ್ಕಾಚಾರಗಳಿಗೆ BigInt ಬಳಸುತ್ತೇವೆ. ಸಂಖ್ಯೆಯ ಕೊನೆಯಲ್ಲಿ n ಸೇರಿಸಿದರೆ ಅದು BigInt ಆಗುತ್ತದೆ.

JavaScript
let starsInGalaxy = 900719925474099123456n;

7. Symbol (ಅನನ್ಯ ಗುರುತು - Unique ID)

ಒಂದೇ ಹೆಸರಿನ ಇಬ್ಬರು ವಿದ್ಯಾರ್ಥಿಗಳಿದ್ದರೂ ಅವರ ರೋಲ್ ನಂಬರ್ (Roll Number) ಹೇಗೆ ಬೇರೆ ಬೇರೆಯಾಗಿರುತ್ತದೆಯೋ, ಹಾಗೆಯೇ ಪ್ರೋಗ್ರಾಮಿಂಗ್‌ನಲ್ಲಿ ಒಂದಕ್ಕೊಂದು ಹೋಲಿಕೆಯಾಗದ Unique ಗುರುತನ್ನು ರಚಿಸಲು Symbol ಬಳಸುತ್ತಾರೆ.

JavaScript
let id1 = Symbol("id");
let id2 = Symbol("id");
console.log(id1 === id2); // Output: false (ಎರಡೂ ಸಂಪೂರ್ಣ ಬೇರೆ!)

ಹಂತ 2: Intermediate Level — Non-Primitive / Reference Data Types

ಮೇಲಿನ 7 ವಿಧಗಳು ಕೇವಲ ಒಂದೇ ಮಾಹಿತಿಯನ್ನು ಹಿಡಿದಿಟ್ಟುಕೊಳ್ಳುತ್ತವೆ. ಆದರೆ ಒಂದೇ ಕಡೆ ನೂರಾರು ಮಾಹಿತಿಗಳನ್ನು ಜೋಡಿಸಿಡಲು ನಮಗೆ ದೊಡ್ಡ ಕಪಾಟು ಬೇಕಾಗುತ್ತದೆ. ಅದೇ Object.

8. Object (ಮಾಹಿತಿಗಳ ಸಂಗ್ರಹ)

ಖಂಡಿತ, ಈ ವಿಷಯವನ್ನು ಚಿಕ್ಕ ಮಕ್ಕಳಿಗೆ ಕಥೆಯಂತೆ ಅರ್ಥವಾಗುವ ರೀತಿಯಿಂದ ಹಿಡಿದು, ಒಬ್ಬ ಪ್ರೊಫೆಷನಲ್ (Pro) ಡೆವಲಪರ್ ಬಳಸುವ ತಾಂತ್ರಿಕ ಮಟ್ಟದವರೆಗೆ ಹಂತ ಹಂತವಾಗಿ ವಿವರಿಸುತ್ತೇನೆ.

ಮೊದಲಿಗೆ, Non-Primitive (Reference) ಡೇಟಾ ಪ್ರಕಾರಗಳು ಎಂದರೇನು?

  • ಮಕ್ಕಳಿಗೆ: ನಿಮ್ಮ ಜೇಬಿನಲ್ಲಿರುವ 10 ರೂಪಾಯಿ ನೋಟು 'Primitive' (ನೇರವಾಗಿ ನಿಮ್ಮ ಬಳಿಯೇ ಇದೆ). ಆದರೆ ನಿಮ್ಮ ಬ್ಯಾಂಕ್ ಅಕೌಂಟ್‌ನಲ್ಲಿರುವ 10,000 ರೂಪಾಯಿ 'Non-Primitive'. ನಿಮ್ಮ ಬಳಿ ಇರುವುದು ಕೇವಲ ಎಟಿಎಂ ಕಾರ್ಡ್ ಅಥವಾ ಪಾಸ್‌ಬುಕ್ (Reference / ವಿಳಾಸ) ಮಾತ್ರ, ಅಸಲು ಹಣ ಬ್ಯಾಂಕ್‌ನಲ್ಲಿದೆ (Memory).
  • ಪ್ರೊ ಗಳಿಗೆ: Non-Primitive ಡೇಟಾಗಳು ಮೆಮೊರಿಯಲ್ಲಿ ನೇರವಾಗಿ ಮೌಲ್ಯವನ್ನು (Value) ಶೇಖರಿಸುವುದಿಲ್ಲ. ಬದಲಾಗಿ, ಆ ಮೌಲ್ಯ ಇರುವ ಮೆಮೊರಿ ವಿಳಾಸವನ್ನು (Reference/Pointer) ಮಾತ್ರ ವೇರಿಯೇಬಲ್‌ನಲ್ಲಿ ಶೇಖರಿಸಿಡುತ್ತವೆ.
ಚಿತ್ರ 4: ಜೇಬಿನ ₹10 ನೋಟು (Primitive) vs ಬ್ಯಾಂಕ್ ಅಕೌಂಟ್ ಮತ್ತು ATM ಕಾರ್ಡ್ (Reference)

ಈಗ ಪ್ರತಿಯೊಂದು ಪ್ರಕಾರವನ್ನು ವಿವರವಾಗಿ ನೋಡೋಣ:

1. Object (ಆಬ್ಜೆಕ್ಟ್)

  • ಮಕ್ಕಳಿಗೆ (Beginner): ಇದೊಂದು ಸ್ಕೂಲ್ ಬ್ಯಾಗ್ ಇದ್ದ ಹಾಗೆ. ಬ್ಯಾಗ್ ಒಳಗೆ ಏನೇನಿದೆ? ಪುಸ್ತಕ, ಪೆನ್ಸಿಲ್, ನೀರಿನ ಬಾಟಲಿ. ಪ್ರತಿಯೊಂದಕ್ಕೂ ಒಂದು ಹೆಸರಿದೆ (ಉದಾಹರಣೆಗೆ: ಬಣ್ಣ: "ನೀಲಿ", ಪುಸ್ತಕ: "ಕನ್ನಡ"). ವಸ್ತುಗಳನ್ನು ಹುಡುಕುವುದು ಸುಲಭ.
  • ಪ್ರೊ ಗಳಿಗೆ (Pro): ಇದು 'Key-Value' (ಕೀ-ಮೌಲ್ಯ) ಜೋಡಿಗಳ ಸಂಗ್ರಹ. ಡೇಟಾವನ್ನು ರಚನಾತ್ಮಕವಾಗಿ (structured) ಶೇಖರಿಸಲು ಇದನ್ನು ಬಳಸಲಾಗುತ್ತದೆ.
JavaScript
let student = { 
  name: "Ravi", // key: value
  age: 10 
};
console.log(student.name); // Output: Ravi

2. Array (ಅರೇ)

  • ಮಕ್ಕಳಿಗೆ (Beginner): ಇದು ರೈಲಿನ ಡಬ್ಬಿಗಳ ಹಾಗೆ! ಇಂಜಿನ್ ಹಿಂದಿರುವ ಮೊದಲ ಡಬ್ಬಿ (0), ಎರಡನೇ ಡಬ್ಬಿ (1)... ಹೀಗೆ ಒಂದರ ಹಿಂದೆ ಒಂದರಂತೆ ವಸ್ತುಗಳನ್ನು ಸಾಲಾಗಿ ಜೋಡಿಸಿಟ್ಟಿರುತ್ತೇವೆ.
  • ಪ್ರೊ ಗಳಿಗೆ (Pro): ಇದು ಒಂದೇ ವೇರಿಯೇಬಲ್‌ನಲ್ಲಿ ಅನೇಕ ಮೌಲ್ಯಗಳನ್ನು ಶ್ರೇಣಿಯಾಗಿ (Ordered collection) ಸಂಗ್ರಹಿಸುವ ಪಟ್ಟಿ. ಇದು 0-index ಇಂದ ಶುರುವಾಗುತ್ತದೆ. JavaScript ನಲ್ಲಿ ಒಂದು Array ಒಳಗೆ Numbers, Strings, ಮತ್ತು Objects ಎಲ್ಲವನ್ನೂ ಒಟ್ಟಿಗೆ ಹಾಕಬಹುದು.
JavaScript
let fruits = ["Apple", "Banana", "Mango"];
console.log(fruits[0]); // Output: Apple (ಮೊದಲ ಡಬ್ಬಿ)

3. Function (ಫಂಕ್ಷನ್)

  • ಮಕ್ಕಳಿಗೆ (Beginner): ಇದೊಂದು ಜ್ಯೂಸ್ ಮಾಡುವ ಮಿಕ್ಸಿ ಇದ್ದ ಹಾಗೆ! ನೀವು ಒಳಗೆ ಹಣ್ಣು ಮತ್ತು ಸಕ್ಕರೆ (Input) ಹಾಕಿದರೆ, ಅದು ಜ್ಯೂಸ್ (Output) ಮಾಡಿ ಕೊಡುತ್ತದೆ. ಒಮ್ಮೆ ಮಿಕ್ಸಿ ಕೊಂಡುಕೊಂಡರೆ, ಎಷ್ಟು ಬಾರಿಯಾದರೂ ಜ್ಯೂಸ್ ಮಾಡಬಹುದು (ಮರುಬಳಕೆ).
  • ಪ್ರೊ ಗಳಿಗೆ (Pro): ನಿರ್ದಿಷ್ಟ ಕಾರ್ಯವನ್ನು ನಿರ್ವಹಿಸುವ ಮರುಬಳಕೆ ಮಾಡಬಹುದಾದ ಕೋಡ್ ಬ್ಲಾಕ್ (Reusable code block). JavaScript ನಲ್ಲಿ ಫಂಕ್ಷನ್‌ಗಳನ್ನು 'First-class citizens' ಎನ್ನುತ್ತಾರೆ. ಅಂದರೆ, ಇವುಗಳನ್ನು ವೇರಿಯೇಬಲ್‌ಗೆ ಅಸೈನ್ ಮಾಡಬಹುದು, ಅಥವಾ ಬೇರೆ ಫಂಕ್ಷನ್‌ಗೆ ಪ್ಯಾರಾಮೀಟರ್ ಆಗಿಯೂ ಕಳುಹಿಸಬಹುದು.
JavaScript
function makeJuice(fruit) {
  return fruit + " Juice ready!";
}
console.log(makeJuice("Apple")); // Output: Apple Juice ready!
ಚಿತ್ರ 5: Array (ರೈಲಿನ ಡಬ್ಬಿಗಳು) ಮತ್ತು Function (ಜ್ಯೂಸ್ ಮಿಕ್ಸಿ)

4. Date (ದಿನಾಂಕ)

  • ಮಕ್ಕಳಿಗೆ (Beginner): ಇದು ನಿಮ್ಮ ಮನೆಯ ಗೋಡೆ ಮೇಲಿರುವ ಕ್ಯಾಲೆಂಡರ್ ಮತ್ತು ಗಡಿಯಾರ. ಇವತ್ತು ಯಾವ ದಿನ, ಸಮಯ ಎಷ್ಟು, ನಿನ್ನೆ ಯಾವ ದಿನವಾಗಿತ್ತು ಎಂಬುದನ್ನು ಹೇಳುತ್ತದೆ.
  • ಪ್ರೊ ಗಳಿಗೆ (Pro): ಇದು JavaScript ನ Built-in ಆಬ್ಜೆಕ್ಟ್. ಜನವರಿ 1, 1970 ರಿಂದ ಈವರೆಗಿನ ಸಮಯವನ್ನು ಮಿಲಿಸೆಕೆಂಡ್‌ಗಳಲ್ಲಿ ಲೆಕ್ಕಹಾಕಿ, ದಿನಾಂಕ ಮತ್ತು ಸಮಯವನ್ನು ನಿರ್ವಹಿಸಲು, ಬದಲಾಯಿಸಲು (format/manipulate) ಅನುಕೂಲ ಮಾಡಿಕೊಡುತ್ತದೆ.
JavaScript
let today = new Date();
console.log(today.getFullYear()); // Output: 2026

5. RegExp (Regular Expression)

  • ಮಕ್ಕಳಿಗೆ (Beginner): ಇದೊಂದು ಪೊಲೀಸ್ ನಾಯಿ ಇದ್ದ ಹಾಗೆ! ಅದಕ್ಕೆ ಒಂದು ವಾಸನೆ (pattern) ತೋರಿಸಿದರೆ ಸಾಕು, ಎಷ್ಟೇ ದೊಡ್ಡ ಗುಂಪಿನಲ್ಲಿದ್ದರೂ ಕಳ್ಳನನ್ನು ಹುಡುಕಿ ಹಿಡಿಯುತ್ತದೆ. ನಮಗೆ ಬೇಕಾದ ಪದ ದೊಡ್ಡ ಪುಸ್ತಕದಲ್ಲಿ ಎಲ್ಲಿದೆ ಅಂತ ಹುಡುಕಿಕೊಡುತ್ತದೆ.
  • ಪ್ರೊ ಗಳಿಗೆ (Pro): ಸ್ಟ್ರಿಂಗ್‌ಗಳಲ್ಲಿ (Strings) ನಿರ್ದಿಷ್ಟ ಅಕ್ಷರಗಳ ಮಾದರಿಯನ್ನು (Pattern matching) ಹುಡುಕಲು ಇದನ್ನು ಬಳಸಲಾಗುತ್ತದೆ. ಇಮೇಲ್ ಐಡಿ ಸರಿಯಾಗಿದೆಯೇ, ಪಾಸ್‌ವರ್ಡ್‌ನಲ್ಲಿ ನಂಬರ್ ಇದೆಯೇ ಎಂದು ಪರೀಕ್ಷಿಸಲು (Validation) ಇದು ತುಂಬಾ ಉಪಯುಕ್ತ.
JavaScript
let text = "Hello World";
let pattern = /World/; // World ಎಂಬ ಪದವನ್ನು ಹುಡುಕು
console.log(pattern.test(text)); // Output: true

ES6 (ಹೊಸ JavaScript) ನಲ್ಲಿ ಬಂದಿರುವ ಅಡ್ವಾನ್ಸ್ಡ್ ಪ್ರಕಾರಗಳು:

6. Map (ಮ್ಯಾಪ್)

  • ಮಕ್ಕಳಿಗೆ (Beginner): ಇದು Object ನಂತೆಯೇ ಬ್ಯಾಗ್, ಆದರೆ ಸ್ವಲ್ಪ ಅಡ್ವಾನ್ಸ್ಡ್! ಸಾಮಾನ್ಯ ಬ್ಯಾಗ್ (Object) ನಲ್ಲಿ ವಸ್ತುಗಳ ಹೆಸರನ್ನು (Key) ಕೇವಲ ಅಕ್ಷರಗಳಲ್ಲಿ (String) ಮಾತ್ರ ಬರೆಯಬಹುದು. ಆದರೆ Map ನಲ್ಲಿ ಹೆಸರಿನ ಜಾಗದಲ್ಲಿ ನೀವು ನಂಬರ್, ಫೋಟೋ ಅಥವಾ ಬೇರೆ ಯಾವುದೇ ವಸ್ತುವನ್ನಾದರೂ ಬಳಸಬಹುದು.
  • ಪ್ರೊ ಗಳಿಗೆ (Pro): Object ನಲ್ಲಿ Keys ಕೇವಲ String ಅಥವಾ Symbol ಆಗಿರಬಲ್ಲವು. ಆದರೆ Map ನಲ್ಲಿ ಯಾವುದೇ Data type ಅನ್ನು (Functions, Objects, Primitives) Key ಆಗಿ ಬಳಸಬಹುದು. ಇದು ಸೇರಿಸಿದ ಕ್ರಮಾಂಕವನ್ನು (Insertion order) ನೆನಪಿಟ್ಟುಕೊಳ್ಳುತ್ತದೆ.
JavaScript
let myMap = new Map();
myMap.set(1, "One"); // ನಂಬರ್ ಅನ್ನು key ಆಗಿ ಬಳಸಲಾಗಿದೆ
console.log(myMap.get(1)); // Output: One

7. Set (ಸೆಟ್)

  • ಮಕ್ಕಳಿಗೆ (Beginner): ಇದೊಂದು ಮ್ಯಾಜಿಕ್ ಬುಟ್ಟಿ. ಈ ಬುಟ್ಟಿಯೊಳಗೆ ನೀವು ಒಂದೇ ತರಹದ 2 ಸೇಬುಗಳನ್ನು ಹಾಕಿದರೆ, ಅದು ಮ್ಯಾಜಿಕ್ ಮಾಡಿ ಒಂದನ್ನು ಮಾಯ ಮಾಡುತ್ತದೆ ಮತ್ತು ಕೇವಲ ಒಂದನ್ನೇ ಉಳಿಸಿಕೊಳ್ಳುತ್ತದೆ! ಅಂದರೆ, ನಕಲಿ (Duplicate) ವಸ್ತುಗಳಿಗೆ ಇಲ್ಲಿ ಜಾಗವಿಲ್ಲ.
  • ಪ್ರೊ ಗಳಿಗೆ (Pro): ಇದು ಕೇವಲ ಅನನ್ಯ (Unique) ಮೌಲ್ಯಗಳನ್ನು ಮಾತ್ರ ಸಂಗ್ರಹಿಸುವ ಕಲೆಕ್ಷನ್. Array ಗಳಲ್ಲಿರುವ ಡ್ಯೂಪ್ಲಿಕೇಟ್ ಡೇಟಾವನ್ನು ಸುಲಭವಾಗಿ ತೆಗೆದುಹಾಕಲು ಇದನ್ನು ಹೆಚ್ಚಾಗಿ ಬಳಸಲಾಗುತ್ತದೆ.
JavaScript
let numbers = new Set([1, 2, 2, 3, 3, 3]);
console.log(numbers); // Output: Set { 1, 2, 3 } (Duplicates ತೆಗೆಯಲ್ಪಟ್ಟಿವೆ)

ಹಂತ 3: Pro Level — ಪರಿಣಿತರು ತಿಳಿದಿರಬೇಕಾದ ಆಳವಾದ ವಿಷಯಗಳು

ನೀವು ಇಂಟರ್ವ್ಯೂ ಎದುರಿಸಲು ಅಥವಾ ದೊಡ್ಡ ಪ್ರಾಜೆಕ್ಟ್ ಮಾಡಲು ಈ 4 ರಹಸ್ಯಗಳನ್ನು ತಿಳಿದಿರಲೇಬೇಕು:

1. Dynamic Typing (ಸ್ವಯಂಚಾಲಿತ ಬದಲಾವಣೆ)

ಜಾವಾಸ್ಕ್ರಿಪ್ಟ್ ಒಂದು Dynamically Typed ಭಾಷೆ. ಅಂದರೆ, ಇಲ್ಲಿ ಒಂದೇ ವೇರಿಯೇಬಲ್‌ಗೆ ಮೊದಲು ಸಂಖ್ಯೆ ಕೊಟ್ಟು, ನಂತರ ಅದಕ್ಕೆ ಹೆಸರನ್ನು (String) ಬದಲಾಯಿಸಬಹುದು. ಜಾವಾಸ್ಕ್ರಿಪ್ಟ್ ತಾನಾಗಿಯೇ ಡೇಟಾ ಟೈಪ್ ಅನ್ನು ಗುರುತಿಸುತ್ತದೆ.

JavaScript
let box = 100;       // ಈಗ ಇದು Number
box = "ನೂರು ರೂಪಾಯಿ"; // ಈಗ ಇದೇ ಡಬ್ಬಿ String ಆಯಿತು!

2. Stack vs Heap Memory (ಮೆಮೊರಿಯಲ್ಲಿ ಡೇಟಾ ಹೇಗೆ ಸೇವ್ ಆಗುತ್ತದೆ?)

  • Primitive Types (Stack Memory): ಇವುಗಳನ್ನು ಕಾಪಿ ಮಾಡಿದಾಗ ಹೊಸ ಜಾಗದಲ್ಲಿ ಅಸಲಿ ಬೆಲೆಯೇ ಕಾಪಿ ಆಗುತ್ತದೆ (Copy by Value). ಒಂದು ಬದಲಾದರೆ ಇನ್ನೊಂದು ಬದಲಾಗುವುದಿಲ್ಲ.
  • Non-Primitive Types (Heap Memory): Object ಅಥವಾ Array ಗಳನ್ನು ಕಾಪಿ ಮಾಡಿದಾಗ ಕೇವಲ ಅದರ ವಿಳಾಸ (Address/Reference) ಮಾತ್ರ ಕಾಪಿ ಆಗುತ್ತದೆ (Copy by Reference).
JavaScript
// Primitive (Stack) - ಜೆರಾಕ್ಸ್ ಪ್ರತಿಯಂತೆ
let a = 10;
let b = a;
b = 20;
console.log(a); // Output: 10 ('a' ಬದಲಾಗಿಲ್ಲ)

// Non-Primitive (Heap) - ಒಂದೇ ಮನೆಯ ಎರಡು ಕೀಲಿಗಳಂತೆ
let user1 = { name: "ರಾಜು" };
let user2 = user1;
user2.name = "ಕಿರಣ್";
console.log(user1.name); // Output: "ಕಿರಣ್" (user1 ಕೂಡ ಬದಲಾಗಿಬಿಟ್ಟಿತು!)

3. typeof ಆಪರೇಟರ್ ಮತ್ತು ಜಾವಾಸ್ಕ್ರಿಪ್ಟ್‌ನ ಪ್ರಸಿದ್ಧ ತಪ್ಪು (Bug)

ಯಾವುದೇ ಡೇಟಾ ಯಾವ ವಿಧದ್ದು ಎಂದು ಪರೀಕ್ಷಿಸಲು typeof ಬಳಸುತ್ತೇವೆ. ಆದರೆ ಜಾವಾಸ್ಕ್ರಿಪ್ಟ್ನ ಆರಂಭದ ದಿನಗಳಲ್ಲಿ ಆದ ಒಂದು ಸಣ್ಣ ತಪ್ಪಿನಿಂದಾಗಿ typeof null ಎಂದರೆ "object" ಎಂದು ತೋರಿಸುತ್ತದೆ!

JavaScript
console.log(typeof "Hello"); // "string"
console.log(typeof 42);      // "number"
console.log(typeof null);    // "object" (ಇದು ಜಾವಾಸ್ಕ್ರಿಪ್ಟ್‌ನ ಹಳೆಯ ಬಗ್!)

4. Type Coercion (ಸ್ವಯಂ ರೂಪಾಂತರದ ಮ್ಯಾಜಿಕ್)

ಜಾವಾಸ್ಕ್ರಿಪ್ಟ್‌ನಲ್ಲಿ ಒಂದು String ಮತ್ತು Number ಅನ್ನು ಕೂಡಿಸಿದರೆ (+), ಅದು ಸಂಖ್ಯೆಯನ್ನೂ String ಆಗಿ ಪರಿವರ್ತಿಸಿ ಪಕ್ಕದಲ್ಲಿ ಜೋಡಿಸಿಬಿಡುತ್ತದೆ. ಆದರೆ ಕಳೆದರೆ (-), String ಅನ್ನು ಸಂಖ್ಯೆಯಾಗಿ ಪರಿವರ್ತಿಸಿ ಲೆಕ್ಕ ಮಾಡುತ್ತದೆ!

JavaScript
console.log("5" + 2); // Output: "52" (ಜೋಡಿಸುತ್ತದೆ - Concatenation)
console.log("5" - 2); // Output: 3 (ಕಳೆಯುತ್ತದೆ - Math subtraction)
ಖಂಡಿತ, ನೀವು ನೀಡಿರುವ "ಜೇಬು ಮತ್ತು ಸೈಕಲ್ ಸ್ಟ್ಯಾಂಡ್" ಉದಾಹರಣೆ ಅತ್ಯದ್ಭುತವಾಗಿದೆ! ಇದೇ ತಳಹದಿಯ ಮೇಲೆ, ಜಾವಾಸ್ಕ್ರಿಪ್ಟ್‌ನ (JavaScript) ಈ ೪ ಪ್ರಮುಖ ವಿಷಯಗಳನ್ನು (Primitive, Reference, Stack, Heap) ಪ್ರತಿಯೊಬ್ಬರಿಗೂ—ಚಿಕ್ಕ ಮಕ್ಕಳಿಂದ ಹಿಡಿದು ಸಾಫ್ಟ್‌ವೇರ್ ಇಂಜಿನಿಯರ್‌ವರೆಗೆ—ಅರ್ಥವಾಗುವಂತೆ ಇನ್ನಷ್ಟು ರಂಜಕವಾಗಿ ಮತ್ತು ಸರಳವಾಗಿ ವಿವರಿಸುತ್ತೇನೆ.

1. ಮಕ್ಕಳಿಗಾಗಿ ಕಥೆ: "ಅಂಗಿಯ ಜೇಬು ಮತ್ತು ಶಾಲೆಯ ಸೈಕಲ್ ಸ್ಟ್ಯಾಂಡ್!"

ನೀವು ಶಾಲೆಗೆ ಹೋಗುತ್ತಿದ್ದೀರಿ ಎಂದು ಕಲ್ಪಿಸಿಕೊಳ್ಳಿ. ನಿಮ್ಮ ಬಳಿ ಎರಡು ರೀತಿಯ ವಸ್ತುಗಳಿವೆ:

  • ಸಣ್ಣ ವಸ್ತು (ಚಾಕೊಲೇಟ್): ಇದು ತುಂಬಾ ಚಿಕ್ಕದು. ಇದನ್ನು ನೀವು ನೇರವಾಗಿ ನಿಮ್ಮ ಅಂಗಿಯ ಜೇಬಿನಲ್ಲಿ (Stack Memory) ಇಟ್ಟುಕೊಳ್ಳುತ್ತೀರಿ. ಬೇಕಾದಾಗ ತಕ್ಷಣ ಕೈಹಾಕಿ ತೆಗೆಯಬಹುದು. ಇದುವೇ Primitive Data.
  • ದೊಡ್ಡ ವಸ್ತು (ನಿಮ್ಮ ಸೈಕಲ್): ಇದು ತುಂಬಾ ದೊಡ್ಡದು, ಇದನ್ನು ಜೇಬಿನಲ್ಲಿ ಇಡಲು ಸಾಧ್ಯವೇ? ಇಲ್ಲ! ಹಾಗಾಗಿ ಇದನ್ನು ಶಾಲೆಯ ಹೊರಗಿನ ದೊಡ್ಡ ಸೈಕಲ್ ಸ್ಟ್ಯಾಂಡ್‌ನಲ್ಲಿ (Heap Memory) ನಿಲ್ಲಿಸುತ್ತೀರಿ. ವಾಚ್‌ಮನ್ ನಿಮಗೆ ಒಂದು ಪಾರ್ಕಿಂಗ್ ಟೋಕನ್ ಚೀಟಿ (@101 - ವಿಳಾಸ) ಕೊಡುತ್ತಾರೆ. ಆ ಚಿಕ್ಕ ಚೀಟಿಯನ್ನು ತಂದು ನಿಮ್ಮ ಅಂಗಿಯ ಜೇಬಿನಲ್ಲಿ (Stack Memory) ಇಟ್ಟುಕೊಳ್ಳುತ್ತೀರಿ. ಇದುವೇ Non-Primitive Data.
ನೆನಪಿಡಬೇಕಾದ ಸೂತ್ರ:
ಸಣ್ಣ ವಸ್ತುಗಳು (Primitive) ನೇರವಾಗಿ ಜೇಬಿನಲ್ಲಿ (Stack) ಕೂರುತ್ತವೆ. ದೊಡ್ಡ ವಸ್ತುಗಳು (Reference) ಮೈದಾನದಲ್ಲಿ (Heap) ಕೂರುತ್ತವೆ, ಆದರೆ ಅವುಗಳ 'ವಿಳಾಸದ ಚೀಟಿ' ಮಾತ್ರ ಜೇಬಿನಲ್ಲಿ (Stack) ಇರುತ್ತದೆ!
ಚಿತ್ರ 6: ಅಂಗಿಯ ಜೇಬು (Stack Memory) ಮತ್ತು ಶಾಲೆಯ ಸೈಕಲ್ ಸ್ಟ್ಯಾಂಡ್ (Heap Memory)

2. ಬಿಗಿನರ್ ಹಂತ: ಕೋಡಿಂಗ್ ಭಾಷೆಯಲ್ಲಿ ಇವುಗಳೇನು?

ಕೋಡಿಂಗ್‌ನಲ್ಲಿ ನಾವು ಡೇಟಾವನ್ನು (ಮಾಹಿತಿಯನ್ನು) ಸೇವ್ ಮಾಡಬೇಕಾಗುತ್ತದೆ.

A. Primitive Data Types (ಸಣ್ಣ ವಸ್ತುಗಳು)

ಇವು ಕೇವಲ ಒಂದೇ ಒಂದು ಸರಳ ಬೆಲೆಯನ್ನು ಹೊಂದಿರುತ್ತವೆ. ಇವುಗಳನ್ನು ಕಂಪ್ಯೂಟರ್‌ನ ವೇಗವಾದ Stack Memory ಯಲ್ಲಿ ಸೇವ್ ಮಾಡಲಾಗುತ್ತದೆ.
ಜಾವಾಸ್ಕ್ರಿಪ್ಟ್‌ನಲ್ಲಿ ಇವು 7 ಇವೆ (ನೆನಪಿಡಲು: NN-BB-SS-U):

  • Number (ಸಂಖ್ಯೆ): let age = 10;
  • Null (ಖಾಲಿ): let box = null;
  • Boolean (ಹೌದು/ಇಲ್ಲ): let isHappy = true;
  • BigInt (ಅತಿ ದೊಡ್ಡ ಸಂಖ್ಯೆ): let stars = 99999999999n;
  • String (ಪದ/ಹೆಸರು): let name = "ಅಪ್ಪು";
  • Symbol (ವಿಶೇಷ ಗುರುತು): let id = Symbol("1");
  • Undefined (ಇನ್ನೂ ಬೆಲೆ ಕೊಟ್ಟಿಲ್ಲ): let score;

B. Non-Primitive / Reference Types (ದೊಡ್ಡ ವಸ್ತುಗಳು)

ಒಂದಕ್ಕಿಂತ ಹೆಚ್ಚು ಬೆಲೆಗಳನ್ನು ಒಟ್ಟಿಗೆ ಗುಂಪಾಗಿ ಇಟ್ಟುಕೊಳ್ಳುವ ಡೇಟಾಗಳಿವು. ಇವು ದೊಡ್ಡದಾಗಿರುವುದರಿಂದ Heap Memory ಎಂಬ ವಿಶಾಲ ಜಾಗದಲ್ಲಿ ಸೇವ್ ಆಗುತ್ತವೆ.

  • Object {} (ಮಾಹಿತಿಯ ಪೆಟ್ಟಿಗೆ): let boy = { name: "ರಾಮು", age: 12 };
  • Array [] (ಪಟ್ಟಿ): let fruits = ["ಸೇಬು", "ಮಾವು", "ಬಾಳೆ"];
  • Function () (ಕೆಲಸ ಮಾಡುವ ಮಷಿನ್): function play() { return "ಆಟ ಶುರು!"; }

3. ಇಂಟರ್ಮೀಡಿಯೇಟ್ ಹಂತ: ಇವುಗಳ ನಡುವಿನ 3 ಮುಖ್ಯ ವ್ಯತ್ಯಾಸಗಳು

ಪ್ರೋಗ್ರಾಮಿಂಗ್ ಮಾಡುವಾಗ ಈ ಎರಡು ಡೇಟಾಗಳು ಬೇರೆ ಬೇರೆ ರೀತಿಯಲ್ಲಿ ವರ್ತಿಸುತ್ತವೆ:

ವ್ಯತ್ಯಾಸ 1: ನಕಲು (Copy) ಮಾಡಿದಾಗ ಏನಾಗುತ್ತದೆ?

  • Primitive (ಜೆರಾಕ್ಸ್ ಮಾಡಿದಂತೆ): ನೀವು ಒಂದು ಬೆಲೆಯನ್ನು ಇನ್ನೊಂದಕ್ಕೆ ಕಾಪಿ ಮಾಡಿದರೆ, ಅದು ಸಂಪೂರ್ಣ ಹೊಸ ಕಾಪಿಯನ್ನು ಸೃಷ್ಟಿಸುತ್ತದೆ.
JavaScript
let a = 50;
let b = a;   // 'b' ಗಾಗಿ ಹೊಸ 50 ನಾಣ್ಯ ಬಂತು.
b = 100;     // 'b' 100 ಆಯಿತು.
console.log(a); // Output: 50 ('a' ಗೆ ಏನೂ ಆಗಿಲ್ಲ, ಅದು ಸೇಫ್!)
  • Non-Primitive (ಒಂದೇ ಸೈಕಲ್‌ಗೆ 2 ಕೀಲಿಕೈ ಕೊಟ್ಟಂತೆ): ನೀವು ಒಂದು Object ಅನ್ನು ಕಾಪಿ ಮಾಡಿದರೆ, ಅಸಲಿ ವಸ್ತು ಕಾಪಿ ಆಗುವುದಿಲ್ಲ. ಬದಲಿಗೆ ಜೇಬಿನಲ್ಲಿರುವ ವಿಳಾಸದ ಚೀಟಿ ಮಾತ್ರ ಕಾಪಿ ಆಗುತ್ತದೆ.
JavaScript
let cycle1 = { color: "ಕೆಂಪು" }; // ವಿಳಾಸ: @101
let cycle2 = cycle1;            // cycle2 ಗೂ ಅದೇ @101 ವಿಳಾಸ ಸಿಕ್ಕಿತು!

cycle2.color = "ನೀಲಿ";          // 2ನೇ ಕೀ ಬಳಸಿ ಸೈಕಲ್ ಬಣ್ಣ ಬದಲಾಯಿಸಿದೆವು.
console.log(cycle1.color);      // Output: "ನೀಲಿ" (ಕಾರಣ, ಇಬ್ಬರ ಸೈಕಲ್ ಒಂದೇ!)
ಚಿತ್ರ 7: ಜೆರಾಕ್ಸ್ ಪ್ರತಿ (Copy by Value) vs ಒಂದೇ ಸೈಕಲ್‌ಗೆ 2 ಕೀಲಿಕೈ (Copy by Reference)

ವ್ಯತ್ಯಾಸ 2: ತಿದ್ದಲು ಸಾಧ್ಯವೇ? (Mutability)

  • Primitive (Immutable): Stack ನಲ್ಲಿರುವ ಬೆಲೆಯನ್ನು ತಿದ್ದಲು ಸಾಧ್ಯವಿಲ್ಲ. ಹಳೆಯದನ್ನು ತೆಗೆದು ಹೊಸದನ್ನೇ ಇಡಬೇಕು. let word = "ಕನ್ನಡ"; word[0] = "ಚ"; ಅಂದರೂ ಅದು ಬದಲಾಗುವುದಿಲ್ಲ.
  • Non-Primitive (Mutable): Heap ನಲ್ಲಿರುವ Object/Array ಒಳಗೆ ಯಾವಾಗ ಬೇಕಾದರೂ ಹೊಸ ವಸ್ತು ಸೇರಿಸಬಹುದು, ತಿದ್ದಬಹುದು ಅಥವಾ ತೆಗೆಯಬಹುದು. let arr = ["ಕ", "ನ್ನ", "ಡ"]; arr[0] = "ಚ"; ಅಂದರೆ ಅದು ["ಚ", "ನ್ನ", "ಡ"] ಆಗಿ ಬದಲಾಗುತ್ತದೆ.

ವ್ಯತ್ಯಾಸ 3: ಹೋಲಿಕೆ ಮಾಡಿದಾಗ (===)

  • Primitive: ಬೆಲೆಯನ್ನು (Value) ಮಾತ್ರ ನೋಡುತ್ತದೆ. 10 === 10 ಎಂದರೆ true.
  • Non-Primitive: ಮೆಮೊರಿ ವಿಳಾಸವನ್ನು (Address) ಮಾತ್ರ ನೋಡುತ್ತದೆ.
JavaScript
let box1 = { item: "ಚೆಂಡು" }; // ವಿಳಾಸ: @111
let box2 = { item: "ಚೆಂಡು" }; // ವಿಳಾಸ: @222
console.log(box1 === box2);   // Output: false (ವಸ್ತು ಒಂದೇ, ಆದರೆ ವಿಳಾಸ ಬೇರೆ!)

4. ಪ್ರೊ (Pro) ಹಂತ: ಇಂಜಿನಿಯರ್‌ಗಳ ತಾಂತ್ರಿಕ ಗುಟ್ಟುಗಳು

1. const ರಹಸ್ಯ (ಅತಿ ಹೆಚ್ಚು ಇಂಟರ್ವ್ಯೂಗಳಲ್ಲಿ ಕೇಳುವ ಪ್ರಶ್ನೆ)

const ಎಂದರೆ ಬದಲಾಯಿಸಲು ಆಗುವುದಿಲ್ಲ ಎಂದು ನಮಗೆ ಗೊತ್ತು. ಆದರೆ const ಬಳಸಿ Object ಸೃಷ್ಟಿಸಿದರೂ, ಅದರ ಒಳಗಿನ ಬೆಲೆಯನ್ನು ಬದಲಾಯಿಸಬಹುದು! ಏಕೆ?

JavaScript
const player = { name: "ವಿರಾಟ್", runs: 100 }; // ವಿಳಾಸ: @505
player.runs = 150; // ಇದು ಕೆಲಸ ಮಾಡುತ್ತದೆ!

ಕಾರಣ: const ಬೀಗ ಹಾಕುವುದು ನಿಮ್ಮ ಜೇಬಿನಲ್ಲಿರುವ ವಿಳಾಸದ ಚೀಟಿಗೆ (@505) ಮಾತ್ರ! Heap ಮೈದಾನದಲ್ಲಿರುವ ಗೋದಾಮಿಗೆ ಅಲ್ಲ. ವಿಳಾಸ ಬದಲಾಗದ ಹೊರತು, ನೀವು ಗೋದಾಮಿನ ಒಳಗೆ ಹೋಗಿ ವಸ್ತುಗಳನ್ನು ಎಷ್ಟು ಬೇಕಾದರೂ ಬದಲಾಯಿಸಬಹುದು. (ಗೋದಾಮಿಗೆ ಬೀಗ ಹಾಕಬೇಕೆಂದರೆ Object.freeze(player) ಬಳಸಬೇಕು).

2. ವಿಳಾಸದ ಲಿಂಕ್ ಕಟ್ ಮಾಡಿ ಹೊಸ Object ತಯಾರಿಸುವುದು (Cloning)

Non-Primitive ಡೇಟಾವನ್ನು ಕಾಪಿ ಮಾಡುವಾಗ ಹಳೆಯ ಡೇಟಾಗೆ ತೊಂದರೆ ಆಗಬಾರದು ಎಂದರೆ, Heap ನಲ್ಲಿ ಹೊಸ ವಿಳಾಸದಲ್ಲೇ ಹೊಸ ಪ್ರತಿ (Clone) ತಯಾರಿಸಬೇಕು.

JavaScript
let user1 = { name: "ಅಪ್ಪು", city: "ಬೆಂಗಳೂರು" };
// Spread Operator (...) ಬಳಸಿ ಹೊಸ ವಿಳಾಸದಲ್ಲಿ ಕಾಪಿ ಮಾಡುವುದು:
let user2 = { ...user1 }; 

user2.city = "ಮೈಸೂರು";
console.log(user1.city); // Output: "ಬೆಂಗಳೂರು" (ಈಗ user1 ಸೇಫ್)

3. ಮೆಮೊರಿ ಕ್ಲೀನಿಂಗ್ (Garbage Collection)

ನಮ್ಮ ಪ್ರೋಗ್ರಾಮ್ ನಡೆಯುತ್ತಿದ್ದಂತೆ ಮೆಮೊರಿ ತುಂಬಿ ಹೋಗಬಾರದು ಎಂದು ಜಾವಾಸ್ಕ್ರಿಪ್ಟ್ ಸ್ವಯಂಚಾಲಿತವಾಗಿ ಕ್ಲೀನ್ ಮಾಡುತ್ತದೆ:

  • Stack Memory (LIFO): ನೀವು ಮಾಡಿದ ಫಂಕ್ಷನ್ (ಕೆಲಸ) ಮುಗಿದ ತಕ್ಷಣ, ಜೇಬಿನಲ್ಲಿರುವ (Stack) ಎಲ್ಲ ವೇರಿಯೇಬಲ್‌ಗಳು ತಕ್ಷಣ ಅಳಿಸಿಹೋಗುತ್ತವೆ.
  • Heap Memory (Garbage Collector): Heap ಮೈದಾನದಲ್ಲಿರುವ ಯಾವುದಾದರೂ Object ಗೆ, Stack ನಿಂದ ಯಾವುದೇ 'ವಿಳಾಸದ ಲಿಂಕ್' ಇಲ್ಲದಿದ್ದರೆ (ಅನಾಥವಾಗಿದ್ದರೆ), ಜಾವಾಸ್ಕ್ರಿಪ್ಟ್‌ನ Mark-and-Sweep ಎಂಬ ಕ್ಲೀನರ್ ಬಂದು ಅದನ್ನು ಕಸದ ಬುಟ್ಟಿಗೆ ಹಾಕಿ ಮೆಮೊರಿ ಖಾಲಿ ಮಾಡುತ್ತದೆ.

5. ಮಾಸ್ಟರ್ ಸಾರಾಂಶ (Cheat Sheet)

ಗುಣಲಕ್ಷಣ Primitive Types (ಉದಾ: Number, String) Non-Primitive Types (ಉದಾ: Object, Array)
ಮಕ್ಕಳ ಭಾಷೆಯಲ್ಲಿ ಕೈಯಲ್ಲಿರುವ ಚಿಕ್ಕ ಚಾಕೊಲೇಟ್ ಮೈದಾನದಲ್ಲಿ ನಿಂತಿರುವ ಸೈಕಲ್ / ಕಾರು
ಮೆಮೊರಿ ಜಾಗ Stack Memory (ಅಂಗಿಯ ಜೇಬು) Heap Memory (ಮೈದಾನ - ವಿಳಾಸ ಮಾತ್ರ ಜೇಬಿನಲ್ಲಿ)
ವೇಗ ಮತ್ತು ಗಾತ್ರ ಚಿಕ್ಕ ಗಾತ್ರ (Fixed) & ಅತಿ ವೇಗ ದೊಡ್ಡ ಗಾತ್ರ (Dynamic) & ಸ್ವಲ್ಪ ನಿಧಾನ
ತಿದ್ದುವಿಕೆ (Mutation) ತಿದ್ದಲು ಸಾಧ್ಯವಿಲ್ಲ (Immutable) ಸುಲಭವಾಗಿ ತಿದ್ದಬಹುದು (Mutable)
ನಕಲು (Copy) ರೀತಿ ಅಸಲಿ ಬೆಲೆಯ ಕಾಪಿ (Copy by Value) ವಿಳಾಸದ ಕಾಪಿ (Copy by Reference)
ಹೋಲಿಕೆ (===) ಅಸಲಿ ಬೆಲೆಯನ್ನು ಹೋಲಿಸುತ್ತದೆ ಮೆಮೊರಿ ವಿಳಾಸವನ್ನು ಹೋಲಿಸುತ್ತದೆ

Stack ಮತ್ತು Heap ಮೆಮೊರಿ — ಸವಿವರ ನೋಟ

ಕಂಪ್ಯೂಟರ್ ಅಥವಾ ಜಾವಾಸ್ಕ್ರಿಪ್ಟ್‌ನಲ್ಲಿ ನಾವು ಬರೆಯುವ ಡೇಟಾವನ್ನು (ವೇರಿಯೇಬಲ್‌ಗಳನ್ನು) ಸೇವ್ ಮಾಡಿಟ್ಟುಕೊಳ್ಳಲು ಬಳಸುವ ಎರಡು ಪ್ರಮುಖ ಮೆಮೊರಿ (ನೆನಪಿನ) ಜಾಗಗಳೇ Stack ಮತ್ತು Heap.

ಇದನ್ನು ಸುಲಭವಾಗಿ ಅರ್ಥಮಾಡಿಕೊಳ್ಳಲು ಹೀಗೆ ನೋಡೋಣ:

1. Stack Memory (ಸ್ಟ್ಯಾಕ್ ಮೆಮೊರಿ) — "ನಿಮ್ಮ ಅಂಗಿಯ ಜೇಬು"

ಇದು ಚಿಕ್ಕದಾದ, ಆದರೆ ಅತಿ ವೇಗವಾಗಿ ಕೆಲಸ ಮಾಡುವ ಮೆಮೊರಿ ಜಾಗ.

  • ಏನು ಸೇವ್ ಆಗುತ್ತದೆ? ಇಲ್ಲಿ Primitive Data ಗಳು (ಅಂದರೆ ಸಣ್ಣ ವಸ್ತುಗಳು: Number, String, Boolean) ಸೇವ್ ಆಗುತ್ತವೆ. ಇವುಗಳ ಗಾತ್ರ ಎಷ್ಟು ಎಂದು ಕಂಪ್ಯೂಟರ್‌ಗೆ ಮೊದಲೇ ಗೊತ್ತಿರುತ್ತದೆ (Fixed Size).
  • ಉದಾಹರಣೆ: ನಿಮ್ಮ ಅಂಗಿಯ ಜೇಬಿನಲ್ಲಿ ಒಂದು ಪೆನ್, ಅಥವಾ 10 ರೂಪಾಯಿ ನೋಟು ಇಟ್ಟುಕೊಂಡಂತೆ. ಇದು ಚಿಕ್ಕದಾಗಿದೆ ಮತ್ತು ನಿಮಗೆ ಬೇಕಾದಾಗ ತಕ್ಷಣ ಕೈಹಾಕಿ ತೆಗೆಯಬಹುದು (ಅತಿ ವೇಗ).
  • ವಿಶೇಷತೆ: ಇದರಲ್ಲಿರುವ ಡೇಟಾಗೆ ಕೆಲಸ ಮುಗಿದ ತಕ್ಷಣ, ಅದು ತನ್ನಷ್ಟಕ್ಕೆ ತಾನೇ ಅಳಿಸಿಹೋಗುತ್ತದೆ (LIFO - Last In First Out).

2. Heap Memory (ಹೀಪ್ ಮೆಮೊರಿ) — "ದೊಡ್ಡ ಗೋದಾಮು ಅಥವಾ ಮೈದಾನ"

ಇದು ತುಂಬಾ ದೊಡ್ಡದಾದ, ವಿಶಾಲವಾದ ಮೆಮೊರಿ ಜಾಗ. ಆದರೆ ಸ್ಟ್ಯಾಕ್‌ನಷ್ಟು ವೇಗವಾಗಿರುವುದಿಲ್ಲ.

  • ಏನು ಸೇವ್ ಆಗುತ್ತದೆ? ಇಲ್ಲಿ Non-Primitive / Reference Data ಗಳು (ಅಂದರೆ ದೊಡ್ಡ ವಸ್ತುಗಳು: Objects, Arrays, Functions) ಸೇವ್ ಆಗುತ್ತವೆ. ಇವುಗಳ ಗಾತ್ರ ಮೊದಲೇ ಗೊತ್ತಿರುವುದಿಲ್ಲ, ಎಷ್ಟು ಬೇಕಾದರೂ ಬೆಳೆಯಬಹುದು (Dynamic Size).
  • ಉದಾಹರಣೆ: ನಿಮ್ಮ ಬಳಿ ಇರುವ ದೊಡ್ಡ ಸೈಕಲ್ ಅಥವಾ ಕಾರು. ಇದನ್ನು ಜೇಬಿನಲ್ಲಿ ಇಟ್ಟುಕೊಳ್ಳಲು ಸಾಧ್ಯವಿಲ್ಲ! ಆದ್ದರಿಂದ ಅದನ್ನು ಊರ ಹೊರಗಿನ ದೊಡ್ಡ ಪಾರ್ಕಿಂಗ್ ಮೈದಾನದಲ್ಲಿ (Heap) ನಿಲ್ಲಿಸುತ್ತೀರಿ.
  • ವಿಶೇಷತೆ: ಇಲ್ಲಿ ಜಾಗ ವಿಶಾಲವಾಗಿರುತ್ತದೆ, ಆದರೆ ವಸ್ತುಗಳನ್ನು ಹುಡುಕಿ ತರುವುದು ಸ್ವಲ್ಪ ನಿಧಾನ.

ಇವೆರಡೂ ಒಟ್ಟಿಗೆ ಹೇಗೆ ಕೆಲಸ ಮಾಡುತ್ತವೆ? (ಅತ್ಯಂತ ಮುಖ್ಯವಾದ ವಿಷಯ!)

ನೀವು ಒಂದು ದೊಡ್ಡ ಡೇಟಾವನ್ನು (ಉದಾಹರಣೆಗೆ ಒಂದು Object ಅಥವಾ Array) ಸೃಷ್ಟಿಸಿದಾಗ:

  1. ಆ ದೊಡ್ಡ ಡೇಟಾ ಹೋಗಿ Heap Memory (ಮೈದಾನದಲ್ಲಿ) ಕೂರುತ್ತದೆ.
  2. ಆ ಮೈದಾನದಲ್ಲಿ ನಿಮ್ಮ ಡೇಟಾ ಎಲ್ಲಿದೆ ಎಂದು ಗುರುತಿಸಲು ಒಂದು ವಿಳಾಸ ಅಥವಾ ಪಾರ್ಕಿಂಗ್ ಟೋಕನ್ ನಂಬರ್ (Address) ಸೃಷ್ಟಿಯಾಗುತ್ತದೆ.
  3. ಆ ಪಾರ್ಕಿಂಗ್ ಟೋಕನ್ ನಂಬರ್ ಮಾತ್ರ ಬಂದು ನಿಮ್ಮ Stack Memory (ಅಂಗಿಯ ಜೇಬಿನಲ್ಲಿ) ಸೇವ್ ಆಗುತ್ತದೆ!
ಒಂದೇ ಸಾಲಿನಲ್ಲಿ ಹೇಳಬೇಕೆಂದರೆ:
ಸಣ್ಣ ವಸ್ತುಗಳು (Primitive) ನೇರವಾಗಿ ಸ್ಟ್ಯಾಕ್‌ನಲ್ಲಿರುತ್ತವೆ. ದೊಡ್ಡ ವಸ್ತುಗಳು (Non-Primitive) ಹೀಪ್‌ನಲ್ಲಿರುತ್ತವೆ, ಆದರೆ ಅವುಗಳ 'ವಿಳಾಸ' ಮಾತ್ರ ಸ್ಟ್ಯಾಕ್‌ನಲ್ಲಿರುತ್ತದೆ.
